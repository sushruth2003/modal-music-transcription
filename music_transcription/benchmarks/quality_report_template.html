05 / Method & evidence

What these results establish—and what they don’t.

Controlled comparison

This study compares decoding and postprocessing options, not alternative transcription models. All variants use the same pinned MuScriptor Large weights, fp16 precision, deterministic decoding, guidance coefficient 1, and prelude forcing. Beam widths 1, 2, and 4 are crossed with automatic or supplied instrument identities. Variant order rotates across recordings to reduce warm-up bias.

Each clip is at most 30 seconds, mono 16 kHz PCM16, with no loudness normalization. The first and last 2.5 seconds provide context and are excluded from note-onset scoring. Notes sustaining into the scoring window still count toward pitch-activity scores.

Reference integrity

URMP uses performance note annotations, not its differently timed score MIDI. GuitarSet uses per-string JAMS note annotations. Slakh references include only stems actually rendered into the mix. MAESTRO uses original aligned performance MIDI from the checksum-verified v3 archive.

Overlapping same-pitch notes remain on separate MIDI tracks in evaluation references. Piano and Slakh offsets use key release, without sustain-pedal extension; duration and activity scores therefore do not fully describe audible sustain.

Scoring the product

The app-export view uses the real model MIDI serializer, including beat-based onset correction and overlapping-note cleanup. We remove only the export’s recorded bar-alignment padding to compare it on the audio clock. We never optimize alignment using the reference. This covers transcription and MIDI export, not PDF engraving, queue performance, or upload-format robustness.

Correct notes require one-to-one pitch matches within 50 cents and onsets within 50 ms. Duration scores additionally require release within the larger of 50 ms or 20% of the reference duration. Instrument scores use the model’s supported program groups. Drum hits use exact MIDI pitches and are reported separately. Velocity, pedal control, pitch bends, and notation layout are outside this scoring suite.

The refinement experiment

A fixed, audio-only spectral-attack rule moves pitched notes by at most 80 ms while preserving duration, except when clipped at the audio end. It searches around the first three harmonics; weak evidence retains the original timing. No reference notes or timings enter this step. This version is an experiment, not a trained onset model.

This is a balanced comparative study, not a universal leaderboard or evidence of unseen-data generalization. No listener panel or subjective quality ratings were collected. Eight clips per source still leave substantial uncertainty.

Selection and scope

Source-balanced averages answer “how do these four categories compare?” They are not weighted to actual user traffic. Recording-level confidence intervals do not account for shared styles, performers, or every dependency across recordings.

Compute and reproducibility

Inference time is CUDA-synchronized. Each setting runs once per recording; model load is excluded. App-export times add CPU beat detection and MIDI export. Refinement adds local CPU time, so it is not a controlled same-host latency comparison. Cost uses the project’s historical L4 rate, not an invoice. An initial connection drop interrupted three in-flight clips; their partial compute and rerun overhead are excluded from this estimate. The initial run record is preserved alongside the resumed run.
