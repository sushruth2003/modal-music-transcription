02 / What changed

Four alternatives, three different strategies.

The two YourMT3+ checkpoints differ in architecture and training recipe. This experiment compares usable pretrained systems; it does not isolate the causal benefit of MoE alone.

Export detail / A product-level fix

Keep the instruments the model predicted.

The YourMT3+ demo combines solo strings into one ensemble patch and merges several other instrument classes for playback. Our adapter keeps its predicted MT3 instrument labels. No model weights, thresholds or note times were tuned. Both exports come from the same inference pass.

Model / recordingsDemo instrument F1Preserved-label instrument F1Change

The MoE model predicts fine instrument labels; the T5 checkpoint’s already-coarse predictions remain coarse. Ensemble figures have training overlap. Distinct instrument tracks can also preserve overlapping unisons that a merged MIDI track would collapse.

05 / Reproducibility

What this experiment can support.

Frozen inputs. The previous 32 excerpts and MIDI references were reused byte for byte: eight real URMP ensembles, eight rendered Slakh bands, eight GuitarSet microphone recordings and eight MAESTRO piano performances. All models receive the same mono 16 kHz audio, resampled internally as required. Upsampling cannot restore higher frequencies; this may disadvantage models trained on higher-rate audio.

Primary evidence. “Official test 16” includes the eight MAESTRO v3 and eight Slakh Redux official test examples. This establishes those datasets’ split membership, not an independent audit of every model’s training corpus. URMP and GuitarSet remain exploratory. Six of our eight URMP clips belong to YourMT3+'s published training split; only IDs 01 and 13 are in its test split. GuitarSet membership is not verified. Do not use the all-32 result alone to claim generalization.

One-to-one note matching. Pitch must agree within 50 cents and attack within 50 ms. Duration-aware matching also requires release within the larger of 50 ms and 20% of reference duration. Notes beginning between 2.5 seconds and 2.5 seconds before clip end are scored. Pitched notes exclude drums; exact drum pitches are scored separately. Sounding-pitch F1 uses 10 ms frames, including notes sustaining into the window.

Timing and note lengths. Alternatives use MIDI in performance time. YourMT3+ uses its native writer with MT3_FULL_PLUS labels instead of the demo’s deliberately collapsed playback vocabulary; the original demo export is retained. No best-fit shift, tempo correction, quantization, reference conditioning or parameter search is applied. MuScriptor’s app comparison removes only documented bar padding. MAESTRO references use key releases without pedal extension; the packaged TransKun checkpoint follows that convention. Other models may learn different release conventions.

Instrument assignment. GM programs share the previous MuScriptor evaluation groups, applied to reference and all instrument-aware predictions. Basic Pitch predicts notes without instrument identity, so its default playback patch is never counted as successful classification. Pitch bends and velocities are not scored. Singing and real commercial mixes are absent from this suite.

Uncertainty. Differences use 5,000 paired recording bootstrap draws, stratified by dataset, with a fixed seed. These intervals describe this small sampled set; they do not correct for model selection or establish a universal Pareto improvement. A model must improve the relevant product outputs as well as speed to justify replacement.

Runtime. Alternatives use two CPU cores, with an L4 for YourMT3+ and TransKun. Their FP32 execution follows the shipped inference code; the YourMT3 helper’s trainer precision setting does not itself cast model weights. Basic Pitch uses ONNX CPU with two inference threads. MuScriptor uses the earlier L4 FP16 run. Alternative timings include resampling, inference and native export; MuScriptor model timings measure decoding, and its app timings include beat analysis and export. First-call lazy initialization is retained; loading, downloads, queueing and network transfer are excluded.

Checkpoints and defaults. YourMT3+ uses the author-hosted Space at revision 5e66c1ea173a8186e0d20432b841d3180cc015b5, the YMT3+ and YPTF.MoE+Multi (noPS) presets, batch size 8 and greedy token generation. TransKun uses package 2.0.1’s bundled v2 no-pedal-extension model and native segmentation. Basic Pitch 0.4.0 uses the packaged ICASSP 2022 ONNX weights and unchanged note thresholds. Full checkpoint hashes and installed packages are in the run files.
